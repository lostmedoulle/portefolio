02 / PORTFOLIO

Three projects.
One feedback architecture.

Observe → validate → act → measure → learn. Each project is the same loop: a sensor (extraction, profiling, interview), a comparator (invariants, tests), an actuator (correction, controlled change) and a memory (versioned knowledge). Interfaces and agents are replaceable adapters.

How I engineer

Separate the audited business core. Keep deterministic rules testable. Let agents discover, explain and propose. Use objective tests and human approval to decide what ships.

How I think: cybernetics, applied

Requisite variety

Deterministic rules absorb the variety we already understand. Agents handle only the residual uncertainty, so the system stays auditable where it matters.

Diagnose before you automate

Automating an undiagnosed process is a painkiller: it suppresses the error signal. Trying to automate a process is the cheapest diagnostic of it.

Disagreement is a signal

When two models apply a business rule differently, the rule is underspecified. Divergence goes back to a human owner instead of being averaged away.

Viable systems

Knowledge is a versioned asset, not a person. I build systems that outlive their creator: tested domain cores, explicit contracts, replaceable interfaces and models.

I write about this in Med's Cybernetic Garden, a French-language research garden on cybernetics applied to enterprise AI, where every idea is tagged as hypothesis, in test or validated. Featured experiment: "The agent is not a production tool, it is a measuring instrument." Founding thesis: I don't write prompts; I write specifications, tests and feedback loops.

Financial Reconciliation & Audit Platform

Business pain. Reconciling pension accounting across the pension ERP, the accounting system and technical ledgers required weeks of manual effort, with fragmented audit evidence and exceptions.

Pension ERP / accounting system → Playwright / automated extraction → normalized datasets
↓
Independent Python reconciliation library: exact / temporal matching, accounting invariants, anomaly classification
↓
Auditable artifacts → SharePoint / Planner → human review, corrections and repeat cycles

Engineering. Python, pandas/Polars, Playwright, Docker, modular domain rules and structured reports. The educational interface explains which controls ran and why a difference was flagged. Bot-operated extraction and multi-user review reduce reliance on a single operator.

Value: pedagogy and risk reduction first. Reviewers see which control ran and why, so they can understand and challenge a result instead of trusting a black box. Reproducible evidence, traceability, earlier anomaly detection and lower key-person dependency. Capacity: an estimated 3–4 weeks of manual reconciliation avoided per foundation cycle.

02

Reusable Pension ERP Migration Pipeline

~1 weekPer migration before: manual mapping and checks
~1 hourPer migration now, cross-checked by agents and a counter-agent
1 coreTested domain library reused for every client

Business pain. Each external client arrives with different source schemas, data quality and pension-specific business rules. Manual mapping creates rework and hidden dependencies.

Customer source → profiling, mapping, quality checks
↓
Private pip-installable domain packages: versioned transformations, identities, invariants and tests
↓
Dagster orchestration → validate / transform / load / compute / compare
↓
Classify exception: client source correction OR reviewed domain-library change
↓
Regression tests → controlled SFTP integration / ERP acceptance

Engineering. Python, Polars/pandas, Dagster, Docker, FastAPI, Ink terminal POCs, Streamlit for lightweight interfaces and API-first boundaries. The domain core is independent of UI, orchestrator and LLM. Rust and polyglot components are considered selectively, not assumed necessary.

Agent layer. Specialized agents propose mappings, diagnose exceptions and rerun validations; changes to audited domain logic require versioning, independent tests and approval. When different models interpret the same rule differently, the rule is flagged as underspecified and returned to its business owner. Confidential processing requires authorized network isolation and egress controls, not VPN alone.

Impact. A migration that took about a week of manual work now runs in about an hour. Results are cross-checked by a multi-agent setup with an adversarial counter-agent, on top of deterministic validation and end-to-end reconciliation, so agents never grade their own work. Each new client reuses the tested domain core instead of starting from scratch. The agent layer only takes over what regression tests show it can do reliably.

AI Discovery & Business Ownership

Business pain. Operational experts know where work hurts, but requirements get lost between employees, analysts and software engineers. The human becomes middleware.

Engineering. Requirements engineering, agent co-coaching, micro-agent roles for review, knowledge capture, RAG, Linear tickets, test gates and process-first Ink POCs. Employees own the problem and acceptance criteria rather than becoming full-time software operators.

Result. ~50 hours/month of employee time freed on a basic process that had already been optimized, after ~2 days of development. The figure counts the employee's time only, not mine.

Limits. Agent agreement is not independent evidence. Use deterministic checks, permissions, evaluation sets, approval thresholds and escalation for regulated workflows.

My reusable systems blueprint

Domain core: isolated, private pip packages with tests, versioning and explicit contracts. Execution: Python/Polars, Dagster, Docker, VPS, FastAPI, SFTP and external APIs. Interfaces: Ink TUI first for process discovery; Streamlit or web UI when justified. Learning loop: RAG, specialized agents, execution history, Linear feedback and regression evaluations.

I do not optimize for more agents or more code. I optimize for lower operating cost, clearer responsibility, reliable decisions and systems that improve without losing control.
